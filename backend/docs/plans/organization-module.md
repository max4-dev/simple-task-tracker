# Модуль организаций

Цель: законченный NestJS API организаций поверх существующей Prisma-схемы.

## Исходные условия

- Авторизация через cookie, Origin guard и ValidationPipe уже подключены.
- Единственный owner задаётся Organization.ownerUserId, FK требует его членства.
- Роли и проектные переопределения наследуются живым образом.
- Внешняя отправка почты пока отключена; schema/миграции не переписываются.

## Контракт

База /organizations, ID UUID. Списки с limit 1–100 и курсором after UUID.
Любой участник может управлять организацией, участниками, ролями и приглашениями.
Чужая организация скрыта за 404; owner-действие от обычного участника даёт 403.
Owner имеет все права и не может выйти/быть исключён до передачи владения.
Права платформенной роли User.role не открывают организации.

## Согласованные решения

- Роли визуальные, все участники имеют одинаковые возможности; owner защищён.
- Проект доступен только явным участникам и owner организации.
- Одноразовые ссылки на email, ручная передача, срок 7 дней; почта не отправляется.
- Безвозвратное удаление только owner с текущим паролем.
- Миграция не нужна: существующие поля permissions сохраняются, но API их не использует.


## Результат проверок

83 unit-теста и 13 HTTP-тестов прошли. Изолированный test:domain прошёл с настоящими PostgreSQL/Redis и HTTP API организаций. Lint, typecheck, сборка и Docker healthcheck успешны. Рабочая БД в проверках CRUD не использовалась.

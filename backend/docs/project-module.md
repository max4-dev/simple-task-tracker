# Модуль проектов

ProjectModule подключён в AppModule. Swagger — `/docs`.
Используются существующие таблицы Prisma; новых миграций не требуется.

## Доступ и роли

Создавать проекты может любой участник организации. Создатель автоматически
становится участником нового проекта с roleId=null — его визуальная роль наследуется
из организации, а не копируется при создании.

Проект доступен только его участникам и текущему owner организации. Другие участники
организации, включая пользователей с платформенной ролью ADMIN, не видят проект
ни в списках, ни по прямому ID. Отсутствующий и недоступный проект возвращают 404.
Все вложенные ID проверяются в контексте указанной организации и проекта.

Роли обозначают специализацию и не ограничивают действия. Любой участник проекта
может менять настройки, управлять участниками, статусами и тегами. В проекте можно
назначить другую роль из каталога той же организации. roleId=null восстанавливает
живое наследование: изменение роли в организации сразу видно в проекте.

Owner организации сохраняет доступ ко всем проектам, даже без ProjectMember.
Список участников содержит только явные членства. Для назначения задач owner тоже
нужно явное членство. Его можно добавить без визуального переопределения роли;
выход из явного членства не лишает owner доступа. Передача владения организацией
сразу меняет owner-доступ; старый owner сохраняет доступ только по своим членствам.

## Проекты

Базовый путь: `/organizations/:organizationId/projects`.
ID организации и проекта — UUID v4.

- `POST /` — создать проект: name, slug, taskPrefix, необязательное description.
- `GET /` — доступные проекты с пагинацией.
- `GET /:projectId` — настройки проекта, включая archivedAt и lastTaskNumber.
- `PATCH /:projectId` — name, slug, description, taskPrefix.
- `POST /:projectId/archive` — архивировать.
- `POST /:projectId/restore` — восстановить.
- `POST /:projectId/leave` — выйти из проекта.
- `DELETE /:projectId` — безвозвратно удалить, только owner организации; body `{ password }`.

Имя — 1–100 символов. Slug — 3–64 символа: строчные латинские буквы, цифры,
одиночные дефисы. Slug и taskPrefix уникальны внутри организации.
Префикс — 1–32 символа, начинается с латинской буквы, остальные символы —
латинские буквы/цифры и одиночные дефисы, например `WEB` или `task-WEB`.
Регистр префикса сохраняется. Описание — до 10 000 символов; null очищает его.
Пропущенные поля при PATCH сохраняют текущие значения.

Префикс разрешено менять только до первого выданного номера задачи. Даже после
удаления всех задач он остаётся зафиксированным; счётчик нельзя менять через API.
Изменение организации проекта, archivedAt и lastTaskNumber через PATCH запрещено.

Списки принимают `limit` от 1 до 100 (по умолчанию 20) и `after` — UUID последней
полученной записи. Ответ: `{ items, nextCursor }`, null означает конец.
Сортировка по ID. У списка проектов дополнительно `state=active|archived|all`,
по умолчанию только active. Скрытые проекты не попадают даже в курсоры страниц.

Архив доступен для чтения, но не для редактирования, изменения участников, статусов
или тегов (409). Восстановить проект может любой его участник или owner.
Повторное архивирование/восстановление идемпотентно. Из архива разрешено выйти,
а owner может удалить его с подтверждением пароля.

Удаление удаляет только данные этого проекта: задачи, назначения, вложения-метаданные,
статусы, теги, участники, связи веток и репозиториев. Пользователи, организация,
её членства и соседние проекты сохраняются. Удаление физических файлов из внешнего
хранилища не реализовано, как и само файловое хранилище. Лимит удаления — 5 запросов
в минуту на IP. Неверный пароль даёт 400 и не меняет данные, обычный участник получает 403.

## Участники

Относительно `/:projectId`:

- `GET /members` — явные участники с пагинацией.
- `POST /members` — добавить существующего участника организации: `{ userId, roleId? }`.
- `PATCH /members/:userId/role` — `{ roleId }`, UUID своей организации либо null.
- `DELETE /members/:userId` — исключить участника проекта.

Ответ участника содержит userId, имя, email, avatarUrl, joinedAt, projectRoleId,
вычисленную role и roleSource (`owner`, `project`, `organization`, `none`).
Полей password, tokenVersion и массивов permission в ответе нет.

Нельзя добавить человека из другой организации или применить чужую роль.
Дублирующее добавление возвращает 409. Участник организации без доступа к проекту
не может добавить себя в него. Выход/исключение удаляет назначения участника на
задачи этого проекта, но сохраняет сами задачи и членство в организации.
Последний явный участник может выйти: owner организации сможет восстановить состав.

## Статусы и теги

Создание проекта, членство создателя и пять начальных колонок сохраняются одной
транзакцией: Бэклог/BACKLOG, К работе/TODO, В работе/IN_PROGRESS, Ревью/REVIEW,
Готово/DONE. Позиции 0–4. Тестовые задачи при этом не создаются.

Статусы относительно `/:projectId/statuses`:

- `GET /` — все колонки по position, затем ID.
- `POST /` — name, необязательные category, color и position; по умолчанию TODO,
  цвет #64748b, позиция после последней колонки.
- `PATCH /:statusId` — частично изменить эти поля.
- `DELETE /:statusId` — удалить пустую колонку. Для занятой передать body
  `{ replacementStatusId }`: задачи переносятся в другую колонку этого же проекта
  атомарно с удалением старой, без изменения номеров и других данных задач.

Последнюю колонку удалить нельзя, включая конкурентные запросы. Без явно выбранной
колонки для переноса занятый статус возвращает 409. Перенос в чужой проект запрещён.
Имя статуса — 1–80 символов, color — #RRGGBB, position — целое 0–1 000 000.
Одинаковые позиции допустимы, для стабильного порядка используется ID.

Теги относительно `/:projectId/tags`:

- `GET /` — список с пагинацией.
- `POST /` — name, branchPrefix, необязательный color.
- `PATCH /:tagId` — частично изменить эти поля.
- `DELETE /:tagId` — удалить неиспользуемый тег; используемый задачами даёт 409.

Имя — 1–80 символов, branchPrefix — 1–32: строчная латинская буква, затем
строчные буквы/цифры/дефисы, например feat или bug. Color — #RRGGBB.
Имена статусов, имена тегов и branchPrefix уникальны в рамках проекта, с учётом
регистра согласно текущим ограничениям БД. Создание веток или запросы к GitHub
не выполняются. API задач, карточек доски и GitHub-интеграция — следующие модули.

## Транзакции и проверки

Запись блокирует строки в порядке организация → проект, затем заново проверяет
членство/owner/архив. Это согласовано с изменением участников и удалением организаций.
Будущий модуль задач должен использовать ProjectAccessService и тот же порядок
блокировок, чтобы учитывать архив и синхронизироваться с настройками доски.
Чтение составных данных использует RepeatableRead. Все маршруты требуют cookie-сессию;
изменяющие запросы — разрешённый Origin. Ответы не кешируются.

- `npm test -- --runInBand` — DTO, частичные обновления, наследование визуальной роли.
- `npm run test:e2e -- --runInBand` — общие HTTP-проверки cookie, Origin и Swagger с заменёнными хранилищами.
- `npm run test:domain` — реальный HTTP API с временными PostgreSQL и Redis:
  изоляция проектов, создание колонок, роли, перенос задач, замороженный префикс,
  архив, удаление по паролю, каскады и конкурентные операции. Рабочая БД не используется.

# Модуль пользователя

Модуль подключён в AppModule. Swagger: `/docs`, OpenAPI JSON: `/docs-json`.
Все маршруты пользователя требуют действующую access-cookie и серверную сессию в Redis.

## Маршруты

- `GET /users/profile` — свой профиль, включая email, телефон и emailVerifiedAt.
- `PATCH /users/profile` — частичное обновление своего профиля.
- `PUT /users/password` — текущий password и newPassword; после успеха нужен повторный вход.
- `GET /users/:id` — профиль коллеги, sharedOrganizations и sharedProjects. ID — UUID.

Общие для всех пользователей поля: имя, avatarUrl, bio, githubUrl, timeZone,
socialLinks, workIntervals, вычисляемый isWorkingNow.
Профиль другого пользователя доступен только при общей организации или проекте.
В текущей модели участник проекта обязательно состоит в его организации, поэтому
проверка общей организации покрывает оба случая. Email и телефон видны коллегам
по общей организации. emailVerifiedAt возвращается только владельцу профиля.
Недоступный и отсутствующий профиль одинаково возвращают 404.

В sharedProjects попадают только неархивные проекты, доступные обоим пользователям.
Owner организации видит все проекты; остальным требуется ProjectMember.
По текущему решению роли обозначают специализацию и не ограничивают действия:
массивы permission и project overrides не участвуют в проверке.
Приватные проекты, чужие организации, пароль, platform role и tokenVersion в ответ не попадают.
Shared-списки пока возвращаются целиком; для больших организаций потребуется отдельная пагинация.

## Обновление профиля

Пропущенное поле сохраняет значение. `null` очищает avatarUrl, bio, phone, githubUrl;
имя и timeZone не могут быть null. socialLinks и workIntervals заменяются целиком;
`[]` очищает список. Все изменения одного запроса атомарны.

Имя — 1–100 символов, описание — до 2000, телефон — международный формат с плюсом.
Ссылки — HTTP(S), GitHub — HTTPS-ссылка на профиль github.com. Максимум 20 социальных ссылок.
URL аватара сохраняется как ссылка; загрузка файлов и проверка содержимого изображения — отдельная функция.

Расписание содержит до 28 непересекающихся интервалов:
weekday от 1 (понедельник) до 7, startMinute 0–1439, endMinute 1–1440.
Конец интервала не входит в рабочее время. Ночную смену нужно разделить по полуночи.
timeZone — IANA-зона; isWorkingNow учитывает переходы летнего времени и не означает online.

Email, права, ID и emailVerifiedAt через PATCH менять нельзя. Смена email потребует
отдельного подтверждаемого сценария. Административные список всех пользователей,
смена глобальной роли и произвольное удаление из старого проекта удалены.
Удаление аккаунта пока не реализовано: оно требует отдельного сценария передачи
владения и обработки членства.

## Подключение авторизации

Ранее AuthModule и UserModule не были подключены к приложению. Теперь действуют
`POST /auth/register`, `POST /auth/login`, `POST /auth/refresh-token`,
`POST /auth/logout` и `GET /auth/me`.
Регистрация и login возвращают безопасные поля пользователя; токены передаются только
в HttpOnly cookie. Почта не отправляется, emailVerifiedAt остаётся null.
Новый пароль — 12–128 символов; при входе допускаются существующие более короткие пароли.

Одна активная сессия на пользователя: новый вход отзывает предыдущую.
Access JWT живёт 7 часов, refresh — 30 дней; TTL Redis и cookie совпадают.
Redis хранит SHA-256 отпечатки случайных подписанных токенов, а PostgreSQL — Argon2-хеш пароля.
Refresh меняет оба токена атомарно: из двух одновременных запросов успешен только один.
Access и refresh различаются типом и не взаимозаменяемы. Bearer-заголовок не принимается.
Каждый защищённый запрос сверяет существование пользователя, tokenVersion и сессию Redis.

Смена пароля проверяет текущий пароль и версию записи, сохраняет новый хеш,
увеличивает tokenVersion и удаляет сессию. Даже при отказе Redis старые токены уже
недействительны за счёт проверки версии в БД; оставшиеся отпечатки удалятся по TTL.
Logout удаляет только ту сессию, которой выполнен запрос.

Старые cookie и Redis-ключи прежнего формата больше не принимаются; после обновления
нужен повторный вход. Старые ключи истекут по исходному TTL.

## Настройка окружения

`JWT_SECRET` обязателен, минимум 32 символа; используйте случайный секрет.
`env:init` генерирует его только при создании нового .env и не меняет существующие секреты.
В уже созданном окружении нужно добавить JWT_SECRET отдельно.
`TRUSTED_ORIGINS` — разрешённые frontend/API origin через запятую, без пути и завершающего слеша.
Значение для разработки: `http://localhost:3000,http://localhost:3001`.
В production задайте реальные HTTPS-origin: cookie получают Secure.

Все изменяющие запросы, включая login/register, должны передавать точный
разрешённый заголовок Origin. Это относится и к curl/API-клиентам.
CORS разрешает credentials только этим origin. Фронт использует `credentials: 'include'`.
Cookie имеют HttpOnly, SameSite=Lax, Path=/; logout очищает их с теми же атрибутами.

Auth-маршруты ограничены 10 запросами в минуту на IP и маршрут, хранилище лимитов
пока локальное процессу. Для нескольких API-реплик нужен общий лимитер на ingress
или Redis. За reverse proxy настройте доверие только своему proxy и ограничения
на ingress; произвольным X-Forwarded-For доверять нельзя.

## Проверки

`npm test -- --runInBand` — DTO, расписание/DST, права, смена пароля, конфигурация.
`npm run test:e2e -- --runInBand` — реальное приложение, guards, cookie, Origin,
валидация и Swagger; Prisma и хранилище сессий в этих HTTP-тестах заменены.

`npm run test:domain` — отдельные временные PostgreSQL и Redis с реальными миграциями,
ограниченной DB-ролью и полным HTTP-приложением. Проверяет регистрацию, профиль,
приватность, доступ к проектам по членству, откат nested writes, смену пароля,
конкурентные обновления, отзыв сессий, cookie, TTL и ротацию refresh.
Рабочая БД, volumes и секреты не используются. Нужны Docker и локальные образы
PostgreSQL из compose.yaml и redis:7-alpine; контейнеры теста удаляются по завершении.

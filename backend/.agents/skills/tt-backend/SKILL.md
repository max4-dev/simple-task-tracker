# Backend и данные

1. Прочитай AGENTS.md, package.json, AppModule/main.ts и затрагиваемый модуль. Определи реальный маршрут от HTTP до хранилища.
2. Зафиксируй входной DTO, ответы/ошибки и права доступа. Настрой Swagger и runtime-валидацию согласованно; декораторы Swagger сами не валидируют запросы.
3. Конфигурация расширяется через config.schema.ts, ConfigSchema и безопасные примеры env. Не логируй значения секретов и полные ошибки драйвера со строкой подключения.
4. Для БД сравни Prisma-модель с историей миграций и реальной целевой схемой. Добавляй новую миграцию, оцени существующие данные и ограничения. Генерируй клиент, не редактируй его.
5. Для auth проверяй email/password + Argon2, cookie-only передачу JWT, отсутствие токенов в JSON и логах, Redis TTL/отзыв, согласованность сроков cookie/JWT/Redis и поведение при отказе Redis.
6. Для refresh, если он затрагивается, проверь ротацию и конкурентные запросы; для logout — отзыв серверной сессии и удаление cookie с теми же атрибутами. Не добавляй почтовый сервис.
7. Проверяй CORS/credentials, SameSite/Secure/HttpOnly, CSRF и доступ к чужим ресурсам. Проверки авторизации должны иметь негативные сценарии.
8. Время выражай через TIME.<период>.IN_SEC/IN_MS с правильными единицами конкретного API.
9. Запусти lint/unit/build; при HTTP-изменениях e2e; для данных/Redis реальные интеграционные проверки на подходящем окружении по AGENTS.md. Укажи, какие зависимости были моками.
10. Для Docker сохрани non-root runtime, отдельный шаг миграций, healthchecks и закрытые сервисные порты. Не запускай destructive reset и не удаляй volumes.

Если найдена существующая несостыковка (модуль не подключён, Swagger не инициализирован, модель без миграции), опиши факт и исправляй только в пределах задачи. Наличие файлов не доказывает рабочую интеграцию.

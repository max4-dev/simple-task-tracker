# Функция с ревью

Этот навык вызывается явно. Он разрешает делегировать исследование/ревью данной задачи; не создаёт разрешения на публикацию или изменение стороннего кода.

1. Прочитай AGENTS.md и git status. Определи критерии готовности, область изменений и существующие пользовательские правки. Не требуй чистого дерева.
2. Если нужно исследование, вызови одного scout с конкретным вопросом и запретом правок. Передай пути и границы, дождись фактов.
3. Реализуй задачу через tt-implement. При необходимости параллельной реализации назначь разным исполнителям непересекающиеся файлы; общий lockfile, генерация и миграции имеют одного владельца.
4. Запусти подходящие проверки. Передай reviewer исходную задачу, точный список изменений этой задачи, затронутые новые файлы и фактические результаты проверок. Не выдавай весь грязный diff за свою работу.
5. Reviewer анализирует без изменений и возвращает подтверждённые проблемы с приоритетом, файлом/строкой, условием и последствием. Основной агент проверяет замечания и исправляет реальные ошибки в пределах задачи, включая существенные P2.
6. После исправлений повтори затронутые проверки и при необходимости ревью. Не запускай бесконечный цикл; повторяющийся блокер опиши с остатком работы.
7. Собери результаты и заверши созданные потоки доступным инструментом. Не объявляй изменения после последнего ревью просмотренными ревьюером.

Если среда не поддерживает субагентов, выполни собственную проверку и явно скажи, что независимого ревью не было. Используй роли scout/reviewer из .codex/agents, если клиент их поддерживает; иначе передай их инструкции доступному инструменту делегирования.

# Работа с агентами в task-tracker

Настройка предназначена для Codex. AGENTS.md также можно использовать в других клиентах с поддержкой этого формата. Открой новую сессию после установки, чтобы клиент перечитал инструкции и список навыков.

## Где находятся настройки

- Корневой `AGENTS.md` задаёт общие правила и направляет к frontend/backend.
- В каждом приложении свои `AGENTS.md`, `.agents/skills/`, `.codex/agents/` и эта документация в `docs/agents.md`.
- Корень содержит относительные ссылки на навыки и роли из приложений: они доступны при работе над сквозной задачей и сохраняются в Git.
- Репозиторий один: `.git` находится в корне. Во frontend/backend не должно быть отдельных `.git` или gitlinks.
- Общие исключения — в корневом `.gitignore`, исключения Next.js и Prisma — в `.gitignore` соответствующего приложения. Lockfile, миграции, AGENTS.md, навыки и настройки ролей сохраняются в Git.

Codex ищет навыки в `.agents/skills` от рабочей папки до корня репозитория и поддерживает ссылки на каталоги. Поэтому локальные копии общих навыков есть в обоих приложениях; при изменении общего процесса обновляй обе. [Документация навыков](https://learn.chatgpt.com/docs/build-skills).

## Примеры запросов

- `$tt-prd Опиши минимальный сценарий создания задачи.`
- `$tt-plan Спланируй список задач с фильтром по статусу, согласуй frontend и backend.`
- `$tt-implement Добавь согласованный сценарий создания задачи.`
- `$tt-refactor Перенеси логику, сохрани HTTP-контракт и значения TTL.`
- `$tt-fsd Проверь размещение компонентов и импорты frontend.`
- `$tt-ui Добавь форму на существующих shadcn-компонентах.`
- `$tt-backend Проверь Redis TTL и отзыв сессии при logout.`
- `$tt-feature-review Реализуй задачу и передай результат независимому reviewer.`

Для небольшой правки можно просто описать задачу. PRD/план не обязательны. Навыки для домена доступны в соответствующем приложении; из корня монорепозитория доступны оба набора.

## Роли

`scout` исследует код, `reviewer` проверяет изменения. Роли не меняют файлы по инструкции. Модель, reasoning effort и реальные разрешения наследуются от текущей сессии; отдельную read-only sandbox TOML роли не устанавливает. Независимые агенты вызываются по запросу или явному `$tt-feature-review`; этот навык отключён для неявного вызова. Если клиент не поддерживает делегирование, агент должен явно сообщить об отсутствии независимого ревью.

TOML-файлы в `.codex/agents/` используют актуальный формат standalone custom agents: name, description, developer_instructions. Дополнительный config.toml для этих ролей не требуется. [Документация субагентов](https://learn.chatgpt.com/docs/agent-configuration/subagents).

## Проверка и сопровождение

Из корня монорепозитория:

```sh
python3 frontend/scripts/check-agent-setup.py
python3 backend/scripts/check-agent-setup.py
```

Из каталога приложения: `python3 scripts/check-agent-setup.py` (Python 3.11+). Проверка читает файлы, валидирует метаданные навыков, роли и локальные ссылки документации; приложение и сетевые сервисы не запускает. После изменения AGENTS.md сверяй команды с package.json. Если добавляешь навык, добавь ссылку на него в корневую .agents/skills при работе с общей папкой.

Настройки не означают, что ранее написанные функции уже подключены: проверяй AppModule/bootstrap, миграции и HTTP-сценарии перед заявлением о готовности. Известные на момент настройки незавершённые интеграции не исправлялись в рамках этой задачи.

# Безопасный рефакторинг

1. Прочитай AGENTS.md, текущий diff и потребителей изменяемых символов. Запиши сохраняемые инварианты и существующие проблемы.
2. Проверь релевантный baseline; отделяй ранее существовавшие сбои от новых. Блокер одной проверки не требует остановки независимых безопасных шагов.
3. Делай небольшие согласованные изменения и обновляй все ссылки через rg. При переносе учитывай DI-модули, runtime-разрешение импортов и client/server границы.
4. Сохраняй HTTP-контракт, статусы, cookie-флаги, значения TTL и единицы времени, содержимое данных и наблюдаемое UI-поведение. Исправление поведения — отдельная явно обозначенная часть задачи.
5. Обновляй тестовые импорты/фикстуры при необходимости; не ослабляй проверяемый контракт. Если пользователь прямо запретил менять тесты — соблюдай запрет.
6. Выполни затронутые тесты, lint и сборку по AGENTS.md. Повторяй проверки после существенных правок, а не весь набор после каждого переименования.
7. Проверь отсутствие старых импортов и ненужных новых barrel-файлов. Откатывай только свои точные изменения; не применяй reset/clean/stash к чужой работе.

Для времени сравнивай численные TTL до/после и используй TIME.<период>.IN_SEC/IN_MS. Для config проверяй отсутствие утечки значения env при ошибке валидации.

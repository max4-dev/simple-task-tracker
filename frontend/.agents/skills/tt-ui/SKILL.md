# Интерфейс таск-трекера

1. Прочитай AGENTS.md, components.json, app/globals.css и близкий существующий компонент. Применяй tt-fsd при размещении нового кода.
2. Используй установленный shadcn base-luma / Base UI, Lucide и текущие tokens/варианты. Сверяй props с локальными типами, не предполагай Radix API.
3. Если нужен новый примитив, проверь изменения генератора перед сохранением: путь <component>/<component>.tsx, единственный экспорт shared/ui/index.ts, отсутствие замен пользовательских компонентов и ненужных зависимостей.
4. Для формы опиши label, ошибки, pending/disabled, повторную отправку и успешный результат. Для списков — loading/empty/error, длинные названия, переполнение.
5. Сохраняй keyboard navigation, видимый focus, доступные имена icon-кнопок, управление фокусом/Escape в диалогах. Переиспользуй поведение библиотечных примитивов.
6. В доступном браузере проверь целевой сценарий, узкий и широкий viewport, длинный текст, клавиатуру и ошибки консоли. Не устанавливай новый браузерный стек автоматически ради одного скриншота.
7. Выполни lint/typecheck/build по AGENTS.md и перечисли фактически проверенные состояния.

Показывай только нужные для сценария элементы. Не вводи новую тему, набор шрифтов, UI-библиотеку или бизнес-функцию без основания в задаче.
